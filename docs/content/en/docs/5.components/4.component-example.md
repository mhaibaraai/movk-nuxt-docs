`ComponentExample` renders a live preview of an example component and shows the source of that example file below it. The source is read at build time, so it always matches the preview.

::note{to="/en/docs/components/component-props"}
Requires `movkNuxtDocs.componentDocs`, with the same prerequisites as [ComponentProps](/en/docs/components/component-props).
::

## Writing examples

Put examples in `app/components/content/examples/` (subdirectories are allowed). The file name is the example name:

```text
app/components/content/examples/
└── AccordionExample.vue
```

Pass the file name to `name`, in PascalCase or kebab-case:

::code-preview
:component-example{name="AccordionExample"}

#code
```mdc
:component-example{name="AccordionExample"}
```
::

## Source display

### Highlights and collapsing

`highlights` highlights the given lines and `collapse` folds long sources:

```mdc
::component-example
---
name: AccordionExample
highlights: [2, 9]
collapse: true
---
::
```

`collapse` also accepts an object to customize the button labels and initial state:

```mdc
::component-example
---
name: AccordionExample
collapse:
  openText: Show source
  closeText: Hide source
---
::
```

### Preview or source only

- `source: false` renders only the preview
- `preview: false` shows only the source with the file name in the header; override it with `filename`
- `prettier: true` formats the source with Prettier before displaying it

## Adjustable options

`options` renders controls above the preview and passes the selected values to the example as props. Options whose name ends with `color` show color swatches:

```mdc
::component-example
---
name: ButtonExample
options:
  - name: color
    label: color
    items: [primary, secondary, neutral]
    default: primary
  - name: label
    label: label
    default: Button
---
::
```

`props` passes fixed initial props, merged with `options`.

## Client-only rendering

When an example uses browser APIs such as `window`, `document` or `setInterval` directly, set `client-only` so the preview renders only on the client and avoids SSR errors:

```mdc
:component-example{name="AccordionExample" client-only}
```

## Extending the example container

Create `app/components/content/ComponentExampleExtras.vue` in your project to overlay extra UI (theme visualizers, playground buttons and so on) inside every example container. The layer ships an empty implementation, and [ComponentCode](/en/docs/components/component-code) renders it too.

| Prop | Type | Description |
| --- | --- | --- |
| `name` | `string`{lang="ts-type"} | The raw `name` value |
| `camelName` | `string`{lang="ts-type"} | The example name in camelCase |
| `pascalName` | `string`{lang="ts-type"} | The example name in PascalCase |
| `effectiveProps` | `Record<string, any>`{lang="ts-type"} | Current values of `props` merged with `options` |
| `options` | `Array<{ name: string, label: string }> \| undefined`{lang="ts-type"} | `options` passed through as is |
| `wrapperContainer` | `HTMLElement \| null`{lang="ts-type"} | Outer container of the example, for positioning overlays |
| `componentContainer` | `HTMLElement \| null`{lang="ts-type"} | Container the example renders into, for scanning the DOM |

The following example, based on [Nuxt UI's `ComponentThemeVisualizer.vue`](https://github.com/nuxt/ui/blob/v4/docs/app/components/content/ComponentThemeVisualizer.vue), overlays a theme visualizer on each example:

```vue [app/components/content/ComponentExampleExtras.vue]
<script setup lang="ts">
import { camelCase } from 'scule'

defineProps<{
  wrapperContainer: HTMLElement | null
  componentContainer: HTMLElement | null
}>()

const route = useRoute()
const slug = computed(() => camelCase(route.path.split('/').pop() ?? ''))
</script>

<template>
  <LazyComponentThemeVisualizer
    :slug="slug"
    :container="componentContainer"
    :position-container="wrapperContainer"
  />
</template>
```

The extension renders on the client only and does not affect SSR output.
